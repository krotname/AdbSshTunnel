# ADB SSH Tunnel — политика конфиденциальности

Дата редакции: 26 октября 2026 года. Приложение: `name.krot.adbsshtunnel`.
Разработчик: Kreout. Контакт по вопросам конфиденциальности: a@krot.name.

ADB SSH Tunnel создаёт SSH-туннель от доверенного компьютера к локальному
ADB Android-устройства. Учётная запись в сервисе разработчика не требуется.
В приложении нет рекламы, встроенных покупок и аналитических SDK.

## Данные на устройстве

Настройки, разрешающие и запрещающие правила сетей, добавленные открытые
SSH-ключи и параметры подключения хранятся на устройстве. Приложение не
отправляет их разработчику. SSH допускает аутентификацию по открытому ключу
и перенаправление только к локальному ADB. Пользователь сам выбирает
доверенные компьютеры и ключи.

## Разрешения Android

- Доступ к местоположению нужен для чтения имени сети Wi-Fi (SSID): Android
  ограничивает получение SSID этим разрешением. Приложение не запрашивает
  GPS-координаты. Фоновый доступ нужен для применения сетевых правил во время
  работы SSH-сервиса, включая момент, когда окно приложения закрыто.
- Доступ к состоянию телефона используется для определения мобильного
  оператора по MCC/MNC. Номер телефона, IMEI, идентификатор абонента и
  контакты не читаются.
- Уведомления используются для отображения состояния работающего туннеля.
- Сетевой доступ необходим для выбранных пользователем соединений.

Отозвать разрешения можно в настройках Android. Это может ограничить
определение сети и работу автоматических правил доступа.

## Внешние соединения

При нажатии «Проверить внешний IPv4» выполняется запрос к `api.ipify.org`.
Сервис получает IP-адрес соединения и обрабатывает запрос по своим правилам.
Эта проверка выполняется по действию пользователя. Разработчик приложения
не получает её результаты. Остальные соединения нужны для SSH и локального
ADB, которыми управляет пользователь.

## Хранение и удаление

Удалить правила и ключи можно в приложении, а все его локальные данные —
очисткой данных или удалением приложения в настройках Android. У разработчика
нет серверной копии этих данных. Если пользователь сам присылает сведения
по электронной почте или в сообщении об ошибке, они используются для ответа
и решения указанного вопроса. Не присылайте закрытые ключи и пароли.
