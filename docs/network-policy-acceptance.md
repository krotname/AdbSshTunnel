# Приёмка постоянного SSH-порта и сетевых списков

Одна команда клиента должна работать при смене системного Wireless Debugging
порта: SSH `19191`, назначение `127.0.0.1:5555`. Назначение внутри SSH виртуальное:
сервер переводит его в проверенный текущий локальный ADB-порт. Оно не создаёт
новый прямой ADB listener. Nonroot не включает и не заменяет системный adbd.

| Сценарий | Ожидаемый результат |
|---|---|
| Системный TLS-порт A → B | Старый сеанс закрыт; та же команда клиента подключается к B |
| Wireless Debugging выключен | Новые каналы запрещены; активный SSH/ADB закрыт |
| Чёрный и белый списки содержат одну сеть | Запрет имеет приоритет |
| Пустой белый список | Listener отсутствует; видна причина |
| Режим чёрного списка, известная сеть | Разрешена, пока нет точного запрета |
| Идентификатор скрыт или разрешение отозвано | Доступ закрыт; видна причина и способ восстановления |
| Геолокация выключена → включена при выданном разрешении | SSID обновлён без перезапуска; интерфейс и служба согласованы |
| Геолокация выключена в активном сеансе | Сеанс отозван; после включения доступ восстановлен только для разрешённой сети |
| Wi-Fi SSID сменился при том же IP | Старые соединения закрыты; новое решение по SSID |
| Wi-Fi и mobile доступны одновременно | Listener только на разрешённых сетях; IMS исключён |
| Добавление, изменение, удаление правила | Сохранение после пересоздания Activity и процесса; немедленный отзыв |
| Другой host/port, exec, PTY, SFTP, reverse, пароль | Отказ |
| Root запрещён или helper отсутствует | Отказ; nonroot не получает root |
| VPN/WireGuard включён и выключен | Политика физических сетей независима; без изменения маршрутизатора |

Все испытания подписанного кандидата выполняются на Pixel: протокол, отзыв,
политика, интерфейс, root/nonroot, порт, смена сети, WireGuard, перезагрузки,
сон и интервалы батареи из RELEASE_PROFILE. Если SIM отсутствует, реальная
mobile/WAN-приёмка остаётся непроверенной; моделирование не закрывает этот пробел.
На рабочем Fold — только установка и штатная настройка готового проверенного APK
без удаления данных и смены host key. Не переносить на него испытания без
отдельного прямого поручения владельца именно на тесты на Fold.
Результаты и ограничения остаются в существующем локальном checkpoint.

## Подтверждённый разовый мобильный сценарий — 12.10.2026

По отдельному прямому поручению владельца на рабочем Fold выполнена одна
успешная SSH→ADB-проверка версии 1.0.0 через Beeline. Клиент подключался
к фактическому IPv4 физической мобильной сети, прочитанному на телефоне,
а не к адресу IMS, VPN или внешнего сервиса определения исходящего IP.
Успех подтверждён ответом ADB целевого телефона через SSH.

1. Проверить устройство, текущую SIM передачи данных, root, ключ доверенного
   клиента и закреплённый host key. Сохранить исходные сетевые настройки.
2. До отключения Wi-Fi запустить на телефоне автономный таймер восстановления
   на 120 секунд. Проверить независимость от управляющей сессии и устойчивость
   к её завершению; откат возвращает Wi-Fi и исходную политику приложения.
3. Временно разрешить только PLMN текущей Beeline (`25099`) в мобильном белом
   списке. Отключить Wi-Fi, не менять SIM, APN, маршрутизатор или VPN.
4. Найти физическую CELLULAR/INTERNET/NOT_VPN/VALIDATED сеть выбранной SIM
   и её IPv4. Исключить IMS и VPN. Проверить listener `19191` на этом адресе.
5. Выполнить один сценарий клиента с закреплённым host key: неизвестный ключ
   отклонён, доверенный ключ принят, канал на виртуальный `127.0.0.1:5555`
   даёт ADB именно целевого телефона, запрос другого порта (`22`) отклонён.
6. Вернуть Wi-Fi и исходные настройки приложения. Через независимый USB-канал
   проверить подключение Wi-Fi, неизменную SIM передачи данных, восстановление
   исходного файла настроек и listener разрешённой Wi-Fi сети. Только после
   этого отменить таймер и удалить его временные файлы.

Все перечисленные результаты получены; исходные настройки восстановлены
с точным совпадением файла. Мобильный белый список после теста снова пуст:
это штатный запрет мобильного доступа, а не ошибка приложения.
Ключи, пользовательские данные и постоянная конфигурация не изменены.

Один успешный сценарий не подтверждает другие операторы, nonroot по мобильной
сети, устойчивость при смене мобильного IP или работу после перезагрузки.
Отсутствие SIM на Pixel остаётся отдельным ограничением. Повторение испытаний
на Fold требует нового прямого поручения; сценарий не даёт постоянного разрешения.
Точные адреса, serial и машинные доказательства сохранены в приватном локальном
checkpoint, без публикации в репозитории.
