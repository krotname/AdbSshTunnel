# Удержание беспроводной отладки

Проверять на тестовом Pixel с независимым защищённым TCP ADB. Не отключать
единственный канал управления рабочего телефона ради испытания восстановления.

1. Без разрешения WRITE_SECURE_SETTINGS переключатель удержания остаётся
   выключенным и показывает команду однократной настройки.
2. Выдать разрешение доверенным ADB, включить non-root SSH и удержание.
   Пока отладка ещё не включалась в разрешённом Wi-Fi, приложение её не включает.
3. Включить Wireless Debugging на разрешённом Wi-Fi. Проверить SSH и ADB через
   перенаправление. Выключить отладку через независимый ADB: приложение должно
   восстановить её и обнаружить новый TLS-порт без ручного ввода.
   Статус удержания должен перейти из ожидания в активный: разрешённый Wi-Fi
   определяется тем же location-aware NetworkCallback, который разрешает SSH.
   Если состояние остаётся в ожидании, прочитать
   `adb shell dumpsys activity service name.krot.adbsshtunnel/com.hardbacknutter.sshd.SshdService`:
   диагностика показывает разрешение, готовность удержания и конкретное условие
   Wi-Fi без ключей, SSID или адресов.
4. Повторить отключение в фоне другого приложения. Проверить свежую SSH-сессию
   с прежним ключом сервера и точную идентичность телефона через ADB.
5. При выключенном удержании, остановленном SSH, отозванном разрешении
   или запрещённом Wi-Fi восстановления нет.
   При неизвестном SSID, VPN и мобильной сети запись настройки запрещена.
6. Вернуть исходные режим root, состояние Wireless Debugging и сетевые правила
   тестового телефона; проверить прежний защищённый ADB и SSH.

Наблюдение Settings.Global и события физических сетей не требуют постоянного
пробуждения CPU. Повторные отказы Android ограничены задержкой до минуты.
Удержание не подтверждает сопряжение и доверие новой сети от имени пользователя.
Перед намеренным отключением отладки сначала выключить удержание в приложении.
Не использовать `Settings.Global.DEVELOPMENT_SETTINGS_ENABLED` как условие:
[Android возвращает сторонним приложениям ноль независимо от системного состояния](https://developer.android.com/reference/android/provider/Settings.Global#DEVELOPMENT_SETTINGS_ENABLED).
Реальный переход между точками доступа, сон и перезагрузка — отдельные сценарии;
восстановление после программного отключения не доказывает их прохождение.
